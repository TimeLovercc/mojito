# Mac 桌面版视觉改版 v2

> 已定：配色看 v2 界面稿再定，第 1 批先按做法 A（B/C token 不变）；问候与对话空状态用 36 号 Songti SC；计划页只换桌面尺度；新增只读信息（第 3 批指标图、晚间未回提示、项目行尾、时间分隔）暂不做。

> **看过 v2 界面稿后已定：**
> - 配色：**B 中性′**（只用于桌面；手机仍是 B/C）。浅色：侧栏 = 毛玻璃 + `#ecece8` α .65，内容 `#f3f3f0`，卡片/输入卡 `#ffffff`，文字 tx `#171716` / tx2 `#52524e` / tx3 `#6f6f6a`（线与叠加由 tx 乘透明度，同原规则）。深色：侧栏 **不透明** `#0c0c0c`（不用毛玻璃，保证层次），内容 `#151515`，卡片 `#1f1f1e`，输入卡 `#262625`，tx `#ececea` / tx2 `#a9a9a5` / tx3 `#8c8c87`。弹层叠色 浅 `rgba(255,255,255,.74)`、深 `rgba(38,38,37,.76)`。毛玻璃模糊的 saturate 用 1.15。brand 与 ok/warn/bad 不变。

> - 界面稿上的实测修正（行高 70/52、按钮顺序"不要 · 同意"、对话状态行点开态、菜单栏空状态等）优先于本文。


## 核心判断

1. **丑在整体，不在某个组件。** 桌面版只换了 5 个字号。间距、按钮、卡片、导航还是手机那一套：每条事项一张卡，按钮铺满整行，一级页也有"‹ 返回"。所以看起来像放大的手机。
2. **外壳只做了一半，字体也没真正生效。**
   - 侧栏刷了不透明的白底（`colors.tabbar`，浅色下是 `#fff`），把毛玻璃盖住了，浅色下侧栏反而比内容区还白。
   - 顶部多出一条 28px 空条。
   - react-native-web 给每个 Text 单独写了 `font: 14px System`，所以在 html 上设字体栈传不下去。Geist Mono 又没有回退字体，汉字会落到别的字体上。中文因此显得发粗、发怪。
   - 颜色用乱了：琥珀用来标"今天"，有品牌色竖条，还有整块的蓝按钮。
3. **目标是 Claude 桌面版那种"安静的文档"，同时有原生 Mac 的手感。**
   - 安静的文档：底色中性，层次只靠明度差、细线和极轻的阴影；时间、来源这类元信息默认收起；AI 回复不套气泡。
   - 原生 Mac：毛玻璃侧栏，红黄绿和顶栏在同一行，按钮小而紧凑。
   - 数据和功能以 Mojito 为准。
4. **手机零改动要靠结构保证，光靠小心不够。** 桌面的页面主体单独写，和手机只共用数据 hook 和纯逻辑小件；手机代码不迁移。少数"两端都改"的正确性修复单独列出，并在真手机上验收。
5. **先对齐基线。** 反馈里的截图可能早于最近几次修复。开工前先在 main HEAD 重新截一套基线。

## 设计原则

1. **安静的文档，不是放大的手机。** 层次按"侧栏 < 内容 < 卡片"排，只靠明度差、细线和轻阴影，而且有量化验收（见"分层"）。不用彩色竖条，不一条一张卡，按钮不铺满整行。
2. **一屏一个主角。** 今天页的主角是"下一步"，对话页是正文，信息流是阅读区。其余内容降到 13/12 号、tx2/tx3 色。实心品牌色每屏最多 1–2 处。状态色只表示状态，旁边一定有数字或文字。
3. **原生 Mac 手感。** 统一工具栏，控件紧凑；小按钮宽度随内容；默认箭头光标；界面文字不可选；焦点环只在键盘操作时出现；滚动不回弹；去掉 WebView 痕迹（右键菜单、图片可拖出窗口）。
4. **只收起能收起的。** 时间、来源在悬停、键盘聚焦或选中时才出现。以下内容常驻：
   - "按了会怎样"，以及修订增减了哪些事项（api.md「大批改进」第 3 条：每张卡写清后果）；
   - 撤销；
   - 最后一条回复的元信息。
5. **只画真实字段，口径说清楚。** 不画百分比；不画会被分页、截断或快照过期带偏的逐天数据；不写数据证明不了的因果。
6. **文档先行，手机零变化。** 先改 `docs/design.md` 并出 v2 界面稿，再动代码。桌面组件只在 `dense` 为真时渲染。

## 桌面 token 表

### 开关

- `dense = Platform.OS==='web' && (window.__TAURI__ 存在 || 启动时窗口宽 ≥ 900)`。
  - 它管字号、间距、控件尺寸、悬停、Enter 发送、桌面 CSS 注入。
  - 这样 380 宽的菜单栏面板也用桌面密度。
- `useWide()` 只管布局。
- 原生端永远不是 dense。

### 颜色用法

- **实心 brand**：每屏最多 1–2 处。只用于主按钮（如"完成""原文 ↗"）、今天角标、发送键。
- **brand 文字或图标**：用于"下一步"文字、链接、"同意"按钮文字（按钮本身是中性底）、选中导航的图标、焦点环。除此之外不用 brand。
- **状态色**：
  - warn：只表示逾期、没复盘、问了没回。
  - bad：只表示被忘了、失败、失联。
  - ok：只表示正常、完成、回了。
- **一律用中性色**："今天""还有 N 天""离结束 N 天"、项目没动静、修订增减的 +/−、图表柱。

### 动效、光标、焦点（desktop-css v2）

- **动效**：
  - 按下 60ms；悬停显隐 120ms（进入延迟 100ms）；常规过渡 200ms，曲线 `cubic-bezier(.32,.72,0,1)`。
  - 按下缩到 .98，发送键缩到 .92。
  - 系统开了"减少动态效果"时全部关闭。
- **选中**：
  - 用 `-webkit-user-select`（WebKit 不认不带前缀的写法）。界面文字不可选，`input, textarea` 显式设为 text。
  - 消息、笔记正文、阅读区、下一步用 `style.userSelect:'text'`。
- **焦点和滚动**：焦点环只在 `focus-visible` 时出现（`0 0 0 3px` brand 35%）；滚动区设 `overscroll-behavior:none`。
- **WebView 痕迹**：非文字区屏蔽 contextmenu；`img, svg` 设 `-webkit-user-drag:none`。

## 外壳（所有页共用）

### 窗口与顶栏

- **第 0 步先花半小时验证。** tao 会把标题栏容器改成约 33px 高、横跨整个窗口宽，可能挡住顶栏按钮。验证方法：在顶栏右侧 y≈10 处放一个按钮，确认点击、悬停、双击缩放都正常。
  - **通过**：
    - 用 `traffic_light_position` 让红黄绿和 52 高的顶栏垂直居中（约 (18,19)，以截图为准）。
    - 删掉 `shell.js` 里 28px 的拖动条，同时删掉 `_layout.tsx` 里 `macMain` 的 `paddingTop: 28`。这两处必须在同一次发布里改，否则层级最高的拖动条会盖住顶栏按钮的上半截。
  - **不通过（退路）**：红黄绿保持默认位置，顶栏从 y=28 开始、高 44。28px 条和顶栏用同一底色，看起来是一整条工具栏，不压字。
- **拖动区**：
  - 顶栏整条用 `dataSet={{ tauriDragRegion: 'deep' }}`；侧栏顶部 0–52 也标成拖动区。
  - 带 tabindex 的 Pressable 会自动排除在拖动区外。个别按钮点不动时，显式加 `data-tauri-drag-region="false"`。
- **顶栏内容**：
  - 左边：标题 16/600 + 副标题 13 tx2。右边：页面级的 28 工具按钮。
  - 平时透明、没有底线；内容滚到下面时才出现 hair 线。滚动状态从滚动区提到页面这一层。
- **导航**：
  - 一级页（对话、系统、通知）顶栏显示页名，不显示"‹ 返回"。
  - 真正的详情页（事项、往期计划、反馈）显示"‹ 上级名"。
  - 页面里不再重复一个 24 号大标题。

### 侧栏 220

- **背景**：Tauri 里透明，透出 `Effect::Sidebar`；浏览器里用上面"分层"表的回退色。右侧一条 hair 线。
- **从上到下**：
  1. 0–52：红黄绿区兼拖动区，不放字。去掉现在的 Mojito 品牌行。
  2. 今天 / 计划 / 项目 / 信息流 / 笔记。"笔记"行右侧写 12 tx3 的 ⌘N，和"对话 ⌘J"同一写法。
  3. 空 16。
  4. 对话 ⌘J / 系统 / 通知。
- **去掉底部整宽的蓝色"笔记"按钮。** 它和"笔记"导航去的是同一页（8.3 少按钮）。⌘N 跳到笔记页并聚焦输入框。
- **导航行**：15/400 tx2。选中时叠 selected，文字 tx 500，图标用 brand（与 原 Mac 界面稿 一致）。
- **计数**（沿用 原 Mac 界面稿 的含义）：

  | 项 | 显示 |
  |---|---|
  | 今天 | brand 角标 = needs_you 总数，0 不显示 |
  | 计划 | mono 12 tx3"k/n" |
  | 项目 | 项目**总数** |
  | 信息流 | last_read_id 之上的新卡片数；已取到的一页里找不到 last_read_id 时写"20+" |
  | 系统 | 三态点（正常 ok / 只有 warn / 有 bad），和系统页、菜单栏共用 `problemsOf` |

### 深浅色同步

- 窗口 `set_theme` 跟随 app 的深浅色设置（跟随系统时传 null），对主窗口和菜单栏面板**两个窗口**都生效。
- 要在首屏渲染前调用。
- 需要在 `capabilities` 里加 `core:window:allow-set-theme`，或者改写成一个 Rust 命令。
- 必须和"侧栏改透明"同一批上线，否则会出现"深色字配浅色毛玻璃"。

## 逐页方案

### 1. 今天

**布局**

- **顶栏**："今天 · 周一 9月28日"。内容最宽 1040。
- **问候块**：问候（拍板 2）。下面一行 13 tx2"两周计划第 5 天 · 离结束还有 9 天"，数字用中性色；这一行 v1 已定。问候块下方留 24。
- **两栏**：左栏是今日重点 → 逾期 → 等你拍板 → 被忘了；右栏是今天日程 → 夜里。
- **小节**：小节标题 13/500 tx2，一张卡，行间用 hair 分隔。空块整块隐藏（8.5a）；今日重点全空时只留一句"今天没有到期的事"。
- **今日重点行**（最小 60）：
  - 左边 56 宽的时间列：今天到期写"10:00"（mono 13 tx），以后的写"9/29"（mono 13 tx2）。
  - 中间：标题 16/500，最多 2 行（不做悬停看全文）；"下一步：" 13 tx2，后接步骤 15/500 brand，最多 2 行。
  - 右边：只在 days_until > 0 时放中性胶囊"还有 N 天"。
  - 没有勾选框；整行点进事项详情。
- **等你拍板**：一张卡，每条一行 AskRow。
  - 左边：类型 12 tx3；标题 15/500；**后果常驻**一行 12 tx2（api.md「大批改进」第 3 条）。计划修订写明增减的事项名，例如"加：写发布说明；减：约 Alex 对稿"，一律中性色。
  - 右边按钮**沿用各类型现有的动作**，不统一改名：
    - 事项草稿、新项目：同意 / 不要；
    - 计划、修订版：只有"同意"（没有 decline 接口），整行点开看详情；
    - 对外草稿：复制正文 / 我已发出 / 不要；

## 向 Claude 桌面版学了什么

| 借鉴点 | Claude 的做法 | Mojito 落在哪 |
|---|---|---|
| 层次靠明度差 + 细线 | 线 = 文字色乘低透明度，0.5px；几乎不用阴影 | 全局 token；另加分层量化验收，防止更平 |
| 叠加式悬停和选中 | 悬停、选中都是中性灰叠加，选中不用品牌色 | 侧栏、项目列表、信息流列表、笔记行（与 原 Mac 界面稿 的 `.nav.on` 一致） |
| 统一顶栏 | 顶栏透明、没有底线，和窗口按钮同一行 | 52 顶栏，滚动后才出线（按第 0 步的验证结果） |
| 限宽、居中的阅读列 | 列宽 768 居中，输入框同宽同中轴 | 对话 720 / 正文 680；笔记、计划、系统、事项详情 720 居中 |
| 助手无气泡，用户浅灰气泡 | 文档流；用户气泡是浅灰、圆角 12 | 对话、事项对话、反馈讨论 |
| 元信息悬停才出现 | 延迟淡入，最后一条常驻 | 对话操作条。Mojito 的"后果"常驻，这一点不学 |
| 工具和系统消息折成一行灰字 | 状态行，点开看详情 | "已转给 Mac""已记成事项"：收起看标题，点开看全文 |
| 输入框：文字行高对齐按钮 | 单行 48、按钮 32；Enter 发送，输入法组字保护；发送键有禁用态 | 对话、笔记、事项的"问问这件事"共用 ComposerBox |
| 正文排版 | 段距 12、列表项 4、粗体 600 | 在现有解析器上扩展 Markdown |
| 字重与字号梯度 | 字重上限 600；24/16/15/13/12 | 全局（和 Mojito 桌面字号一致） |
| 大号衬线问候 | 只用于问候 | 拍板 2 |
| 空状态极简 | 只有问候和输入框 | 对话空状态 |

- 陶土色：它是 Anthropic 的身份色，而且和表示逾期的琥珀太接近。
- 衬线排中文正文。
- 不透明侧栏：8.4 已定毛玻璃。
- 首页式的今天页：Mojito 的今天页是行动面板。
- 侧栏顶部的"新建"行：Mojito 的笔记已经是一级页，⌘N 直达，再加一行就是重复入口。
- 红色行内代码：红在 Mojito 里表示失败。

## 需要你拍板（4 个）

1. **桌面视觉取向（看 v2 稿一次定）：配色和侧栏形态。**
   - **A（推荐）**：B「冷静蓝」和 C「浅色纸面」的 token 全部不变，只学 Claude 的版式、字体、"线和叠加都由文字色乘透明度得到"的做法和轻阴影。手机不受影响；浅色靠三层明度差和量化验收解决"太白太平"。
     - 放弃的：Claude 那种偏暖、略带纸感的底色。
   - **B**：桌面单独一套中性色。仿 Claude v2（浅 `#f9f9f7` / `#f3f3f0` / `#fff`，深 `#151515` / `#111` / `#1a1a19`），或者更暖的 v1（`#faf9f5` / `#262624`）。品牌蓝和状态色不动。
     - 注意：B 的浅色内容底比现在的 `#f3f4f6` 更白，和"浅色太白"的反馈相冲突，需要更依赖卡片线和阴影。
   - **侧栏形态**：推荐贴边加右侧细线（Claude 桌面版的做法，Tauri 能稳定做到）。备选是内缩 8px 加圆角的浮起玻璃（macOS 26 的 Finder / 备忘录样式）。两种都画在 v2 稿里。
2. **问候字体**：今天页问候和对话空状态这两处，用 36 号 Songti SC，还是 24 号苹方 600？
   - **推荐试 Songti**：只用这两处，最有 Claude 味；不喜欢时改回只是改一个 token。
3. **新增的只读信息（按 0.3 要你点头）**：推荐都要，每项都可以单独去掉。
   - a. 系统页检验指标图：本期每天的打开次数和晚间问/回，替换现在的两个数（第 3 批）。
   - b. 晚间提问还没回时的提示：侧栏"对话"行亮一个点，输入框占位字换成"回一句：今天推进了什么…"，菜单栏加一行"回一句 ›"。这一项直接服务核心循环。
   - c. 项目列表行尾"N 件 · N 天前"。
   - d. 对话里的时间分隔（跨天或相隔 ≥30 分钟）。
4. **计划页（8.3 定了"暂不动"）**：
   - **推荐"只换尺度"**：结构和文案都不变，只换桌面字号、间距、卡片和按钮尺寸，再加上两端都做的期号修正。

## 未采纳意见

- **用 markdown-it 重写 Markdown**（可行性 #10）：没有采纳。现有的按行解析器本来就把单个换行当换行（每日邮件卡需要这样），也接好了 RichText 的行内转换。回复按 8.7 只写短段落和列表，在现有解析器上补行内代码、引用、缩进层级就够了，不必引入新依赖。补完仍不够用时再换。
- **桌面数字改用系统字体加 tabular-nums**（可行性 #2 的备选）：没有采纳。8.1 和 8.4 用户已定数字用 Geist Mono；给 mono 字体栈加苹方回退，就能解决汉字落到 mono 里的问题。
- **在 android 下打印 token 表逐项比对**（完整性 #1）：不需要了。已采纳"手机代码不迁移、桌面单独写页面主体"（可行性 #4），手机取值不会变，改用真手机 adb 截图兜底。
- **按天画"问了 / 回了 / 笔记数"的核心循环条**（数据真实性 #2 的替代方案）：暂不做。`/metrics` 里没有笔记数，逐天去数要翻页请求 `/records`。检验指标图已经覆盖"问了 / 回了"；笔记数等 hub 在 `/metrics` 里提供后再加。
- **项目详情改写"近 7 天提交 ≥20 · 快照 X 前"**（数据真实性 #1 的替代方案）：没有采纳。连同活动条整块不做，不新增显示。
- **侧栏默认用内缩浮起的玻璃**（完整性 #9）：部分采纳。两种形态都画进 v2 稿由用户选；推荐贴边，因为这是 Claude 桌面版的做法，而且 Tauri 的整窗毛玻璃做内缩不稳定。
- **在 api.md 加字段区分已关闭计划的来历**（数据真实性 #6）：不在本计划里改，只作为待办交给维护会话决定。本计划先按 (start, end) 合并期号。
- **用 mask-image 做顶部和底部渐隐**（可行性低 #3）：改成绝对定位的渐变 View，只留输入卡上方一条；顶部改用"滚动后出线"，因为 mask 会把滚动条也一起渐隐。
